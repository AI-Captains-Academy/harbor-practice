# 🔧 1.2: The 15-Minute VPS Setup (Plus Hygiene)

**🎬 Clip:** `1.2-vps-setup-hygiene.mp4` (~10 min) · source 06:06–15:53

---

You can be live with a secure HTTPS site in a single evening.

I'm not exaggerating. Especially compared to when I started doing this in 2020 — and especially compared to when Ron started in the 90s. This is all one-click setup now.

Here's the whole path, start to finish.

## Step 1 — Pick a provider

I use *DigitalOcean*. *Hetzner* gets good reviews. *Hostinger* works too, though I'm not its biggest fan.

(One captain in the workshop runs Hostinger for VPS plus AWS for other work — two providers, two purposes. That's normal. You don't have to pick one forever.)

The choice barely matters for your first one. Pick one with a clean dashboard and a $5–$6/month entry tier. Move on.

## Step 2 — Pick an operating system

*Ubuntu* is the default. Why? Honestly... adoption.

It's a Linux distribution. It doesn't do anything special no other distribution does. It's just *the one* everyone uses — so every tutorial, every Stack Overflow answer, every AI has seen it a million times. Red Hat used to be king, then IBM bought it and it got weird. CentOS had its moment. Now it's Ubuntu.

(If you're doing Docker-based work specifically, *Alpine* is popular because it's tiny. Don't worry about that yet.)

These are all free and open source. Pick Ubuntu. Move on.

## Step 3 — Set up an SSH key (not a password)

This is the one step people skip, and it's the one that matters.

An *SSH key* is a pair of encrypted files. Your *private key* lives on your computer. The *public key* goes inside the server. When you connect, the server checks your private key against its public key — and if they match, you're in. No password to brute-force.

When you create the VM, the provider will say "add an SSH key." **Don't skip it.**

If you've never made one, Google "generate SSH key" with your operating system. It's a one-line command and a 3-minute walkthrough. Do it once, use it forever.

## Step 4 — Get something on screen

Once you're in the terminal, the whole "hosting a website" magic reduces to roughly this:

```bash
apt install caddy
echo "I am online" > /var/www/html/index.html
```

*Caddy* is a lightweight web server. That `echo` command writes three words into a file called `index.html`. Whatever lives in that file is what shows up in a browser.

Go to your server's IP address. It says "I am online."

(That's it. That's hosting. Everything after this is just complexity stacked on top of that same idea.)

You get an IP address before you ever buy a `.com`. So you can test immediately.

## Step 5 — Lock the doors (basic hygiene)

A lot of providers set this up automatically when you spin up the container. Not all of them. So make sure it's done.

**Firewall.** Only a few *ports* stay open; the rest are blocked. A port is just a numbered door into your server. You need three:

- **22** — SSH (how you log in)
- **80** — HTTP (unsecured web traffic)
- **443** — HTTPS (secured web traffic)

Everything else stays shut. Fewer open doors means fewer ways in for unwanted visitors.

**Unattended upgrades.** A package that patches security holes while you sleep. Your OS and installed packages need updating — always. This automates it.

**Non-root user.** Don't log in with your *root* account (the one with every permission). Log in as a regular user and type `sudo` when you need to do an admin thing.

I'll be honest... I never do this. (Ask me how that's going.) But it's good practice and I'm telling you because it's right, not because I follow it.

**Snapshots.** A snapshot is a backup of your server's current state. Take one *before* you experiment. If something breaks horribly, you restore the snapshot and you're back to working.

Ask me how I know what happens when you don't do this... and how frustrating it is. (I'm not making that mistake again.)

## Key takeaways

- Four choices get you online: provider (DigitalOcean / Hetzner), OS (Ubuntu), SSH key (not a password), and a web server (Caddy).
- An *SSH key* is an encrypted key pair — private on your machine, public on the server. Skip it and you're asking to get hacked.
- Three ports stay open: **22** (SSH), **80** (HTTP), **443** (HTTPS). Block the rest.
- **Snapshots before experiments** — non-negotiable. The restore button is the only thing between you and a ruined evening.
- You can have a live, secure site in one evening. This is not 2020 anymore.
