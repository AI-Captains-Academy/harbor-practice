# 📦 1.3: Docker, Cloudron & Your First Real App

One website on one server is easy. The moment you want a *second* thing on that same box, life gets sticky.

That's where containers come in — and once the concept clicks, you stop fighting your server and start treating it like real infrastructure.

## Docker: multiple computers on one computer

Without *Docker*, you install everything directly on the server. One app, one website, done. Add a second app and the two start stepping on each other's toes — same port, same file paths, same dependencies. It gets messy fast.

Docker fixes this with *containers*. Each app runs inside its own isolated box with its own operating system, but they all share the physical machine's resources.

(Ron's framing, which I love: think of a container as a separate computer. You can have four or five computers running on one computer. That's the whole mental model.)

You do *port forwarding* so different ports serve different apps. And you put a *reverse proxy* — like Nginx — in front as one front door that routes traffic to the right container.

## Keep your secrets in a .env file

This is non-negotiable and I'll keep saying it:

**Never hardcode API keys, passwords, or secrets inside your code or inside any served file.**

Keep them in a *.env* file — the *environment variables* file. Your app reads from it at runtime. The file stays on the server, never gets served to a browser.

(We know this one well as cloud code users. Same rule on a server.)

## Something has to restart your app when it crashes

Your app *will* crash. Something needs to bring it back.

*systemd* is the suite of commands that manages services on Linux. It lets you install a service so it restarts on reboot, stop it, check its status, restart it manually.

(Confession: when I first saw "supervision" on the slide, I didn't fully know what it meant either. Ron walked us through it — it's just the tool that keeps your stuff running without you babysitting it.)

## Cloudron: the app store for your server

Here's where it gets practical. *Cloudron* is a dashboard you install on a VPS that lets you one-click deploy open-source apps into Docker containers.

Nginx, Wikipedia, WordPress, a self-hosted email client... all running in their own containers on the same server. You go to their app store, pick one, click install, and all the configuration is done for you.

(The configuration that takes a weekend from scratch — Cloudron does it in 30 seconds.)

It also gives you:

**Monitoring.** A live graph showing CPU percentage, RAM used, disk usage. You can actually watch your server. (I saw a spike to 55% in the demo — you'd never notice that without a dashboard.)

**Per-app backups.** Not just whole-server backups — *per app*, on a schedule, stored somewhere else (a separate cloud-storage bucket — think a rented hard drive online, like DigitalOcean Spaces). If one thing breaks, you restore just that one. I've rebuilt my Cloudron three times now. Export the good backups, start fresh, import. (It gets bloated after a couple years. Worth a clean slate.)

**Domains.** Install an app, pick which domain or subdomain it lives on. Cloudflare handles the wiring. Genuinely convenient.

**Support forum.** Excellent. Real humans, real answers.

Cloudron has a free tier now — two apps, no cost. (Cloudron changed its model once before — verify at publish.) It used to be fully open source, then the maintainers needed to make money, so the full feature set moved to paid plans. I'm not sponsored to say any of this — I just like the product.

## The AI alternative (where this is heading)

But let me flag something...

It's getting easy enough to build your *own* Cloudron that you may not need it. Rent a VPS, install cloud code, and say: *"Set up Docker, install these five apps in containers, balance the load, and make sure it stays up."* It does it. (Costs time and tokens — which barely hurts while tokens are subsidized.)

For something simple — a backend that processes your website's forms — you don't need an app store. You tell the AI what to build, it builds it locally, SSHs into the VPS, deploys it, and wires it to your frontend.

I still run Cloudron for public-facing stuff because it's robust and battle-tested. But the gap is closing.

## Key takeaways

- *Docker* runs isolated containers on one machine — "multiple computers on one computer." A *reverse proxy* (Nginx) is the one front door routing traffic to each.
- Secrets go in a *.env* file, never in code or served files.
- *systemd* restarts your app when it crashes — something has to babysit uptime.
- *Cloudron* is a freemium dashboard (free for 2 apps, paid above that) that one-click deploys open-source apps, monitors your server, and does per-app backups to external storage.
- The AI route (vibecode your own dashboard) is closing the gap — simple backends don't need an app store anymore.

## Try this

- [ ] Run two nginx containers side by side: `docker run -p 8080:80 -d nginx` and `docker run -p 8081:80 -d nginx`. Visit `:8080` and `:8081` in your browser. Two computers on one computer, felt.
- [ ] **Leak drill:** put a fake API key inside a served `index.html` → `curl` it from your laptop → watch the key leak in plain text → move the key to a `.env` file → `curl` again → confirm it's gone. (This is the habit that saves you when it's a *real* key.)
