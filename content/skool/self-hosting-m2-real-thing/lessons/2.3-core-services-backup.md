# ⚙️ 2.3: Core Services to Self-Host (Agents, Media, Storage & Backup)

**🎬 Clip:** `2.3-core-services-backup.mp4` (~12 min) · source 38:47–50:56

---

Now the fun part. You've got a machine, it's on a safe network, it's reachable through a tunnel... what do you actually *put* on it?

Here's the menu — ordered by what matters most to this community.

## Number one: AI agent runtimes

This is the whole reason most of you are here.

I run *Hermes* on two Raspberry Pis. One is our family domestic assistant. One is my creative assistant. They're both on 24/7 — still running when my laptop's closed, still answering when I ping them from my phone, still doing things overnight if I ask.

(That's the shift. An agent on your laptop sleeps when you sleep. An agent on a Pi doesn't.)

Here's why a Pi is enough: if you're using an *external provider* — Venice, Anthropic, an API key — your machine isn't doing any inference. It's just processing and calling out. A 4 GB Pi handles that fine. You only need serious hardware if you're running models *locally*.

The runtime options: **Hermes**, **OpenClaw**, **NanoClaw**, **Ollama**, **n8n**. n8n on a Pi is interesting — it can be the backend for a Netlify or Vercel frontend. Most workflows don't need much compute; they're just gluing pieces together deterministically.

## Your first home service: a static site

If you want a gentle first project, host a static website with Caddy through a Cloudflare tunnel.

Zero database. Zero state. Nothing to lose. My homepage *could* run this way — low traffic, no accounts, no risk.

(Back in the day, *this is how all websites ran*. The Pirate Bay started on someone's home server. Hosting from your house isn't crazy — it's the original way. You just have to understand the networking so it's safe and performant.)

## Relay services — connecting your networks

**Tailscale (or WireGuard).** A *mesh VPN* that connects your phone to your home network from anywhere. I run *Home Assistant* — security cameras, home automations, the grocery list, my Hermes agent — all in one dashboard. But it's only reachable on home Wi-Fi... unless I'm on Tailscale. Then my phone is virtually "at home" from anywhere.

(Tailscale is proprietary. I want an open-source alternative and haven't found one I trust yet. It works, the AI sets it up for you, and I'm being honest about the compromise.)

**Syncthing.** Sync files between all your machines — iOS, Android, Mac, Windows, your servers. No iCloud. I haven't had great luck with it, but it works for a lot of people.

**Self-hosted Gitea.** Your own GitHub. I use it to sync cloud code workflows on my laptop with Hermes workflows on my Pi — a cron job on each pulls from the local Gitea before running. Skills, knowledge base, everything stays in sync with *version tracking*. (Better than Syncthing for this, because Git gives you history.)

**Matrix / Element.** A self-hosted, end-to-end-encrypted chat server. Think Telegram, but you own it. I'm moving my family and team off Telegram for anything private, and you can connect your agents to it too.

**One rule:** Tailscale alone can replace the Cloudflare tunnel for *private* services. If it's just for you, install Tailscale and skip exposing anything at all.

## Media server (the most common home project)

**Jellyfin** or **Plex** — a media server that connects your Pi to your TV, pulls files from a USB drive on your router, plays your movies.

Host your *own* media — things you made, things you own. Be careful, Captain. Downloading stuff from someone else's home server is how the notice hits your door.

The *arr* stack — **Sonarr**, **Radarr**, and friends — automates finding, sorting, and renaming media for your library. (I have big ambitions for this and haven't gone deep yet. It's the most common self-hosted project for a reason.)

**Storage and transcoding** pair with this. Pulling family photos off iCloud onto your own server. A media server that transcodes a 4K file down so it doesn't burn your laptop's CPU while you're working.

## The 3-2-1 backup rule

Everything above is worthless if you lose it when a drive dies.

**3 copies, 2 different media, 1 off-site.**

- Copy 1: your main machine.
- Copy 2: a backup drive you plug in periodically (or a second machine on the network).
- Copy 3: an encrypted cloud backup, somewhere off-site.

Automate it. Tell your agent: *"Every week, back everything up to this drive on this part of the network."* If it's all on Tailscale, the agent can reach every drive from anywhere.

(Try restoring from your backup *once*. Make sure the whole workflow actually works before you need it. An untested backup is a wish, not a backup.)

## Monitoring and the unglamorous truth

A VPS handles uptime for you. At home, *you* handle it.

**Uptime Kuma** watches your services and tells you when something's down. You check the logs. You run updates. You make sure things stay on.

I check my Bitcoin server a couple times a week... mostly to make sure the kids didn't unplug it or knock it over. (That's the reality of home hosting. Hardware lives in a house, and houses have children.)

## Where you'll use this

This is the payoff lesson. The agents, the harnesses, the autonomous Pi agents from the main curriculum — they all become *real* when they're running on a box you own, reachable from your phone, doing work while you sleep. Everything before this lesson was setup. This is the use.

## Key takeaways

- **AI agent runtimes** are the #1 home-hosting use case for this community — a Pi running Hermes, calling an external API, costs almost nothing and runs 24/7.
- A **static site through Caddy + Cloudflare tunnel** is the perfect first home service — zero state, nothing to lose.
- **Relay services**: Tailscale (mesh VPN for private access), Syncthing (file sync), Gitea (self-hosted Git for agent sync), Matrix (private encrypted chat).
- **Media servers** (Jellyfin/Plex + the *arr* stack) are the most common home project — host your own media, be careful about sources.
- **3-2-1 backup**: 3 copies, 2 media, 1 off-site. Automate it, and *test the restore once*.

## Try this

Two failure-experience labs. Judgment comes from scars — so we make two, on purpose.

- [ ] **Restore drill:** back up a folder → delete the original → restore it. Any step that fails means the backup was a wish, not a backup. (An untested backup is the most expensive thing you own — it costs nothing until it costs everything.)
- [ ] **While-you-sleep proof:** set an hourly cron job (cron is Linux's built-in scheduler — it runs a command on a timer) on your always-on device that appends a timestamp to a file. Check that file from your phone the next morning. If the timestamps ran through the night, your server is 24/7 — in practice, not theory.
- [ ] **Tailscale free tier:** install Tailscale on your laptop and your phone. Join them to the same tailnet. (Personal plan: $0 forever, unlimited devices, up to 6 users. Tailscale restructured its plans recently — verify at publish. Enough for this lab and well past it.)

Then comment: **did the restore work first try?** Honest answers only. (If it didn't, that's the most valuable thing this lesson taught you.)
